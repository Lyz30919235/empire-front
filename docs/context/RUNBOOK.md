# 操作与验证入口

这里只补充前置条件、操作路由和验证边界，已有步骤与命令沿用原章节。文档描述不构成执行授权；执行前核对当前任务范围和工具是否存在。本页命令与步骤均为操作说明，未由本次文档维护执行；实际执行日期、对象与结果只在 [NOW：本轮核验](NOW.md#本轮核验) 定位。

## 开始游戏与双人联机

- Windows 玩家运行方法沿用 [Windows 开始游戏](../../godot/README.md#windows-开始游戏)。前置条件为对应 Windows 64 位游戏包；包的验证及安装状态查 [NOW：完成与证据边界](NOW.md#完成与证据边界)，不能由文件存在推断安装通过。
- 双人方法沿用 [双人 IP 直连](../../godot/README.md#双人-ip-直连)。双方版本一致，主机 IP 与 TCP 端口可达；默认端口 47653。不要求特定 VPN，不自动修改网络或防火墙设置。
- 验证时区分同机回环与真实两台设备：同机 `127.0.0.1` 仅证明本机路径。跨设备需双方完成建房、准备、换牌、动作同步及对应重连场景，并明确记录设备与网络范围；现有跨设备缺口见 [RISKS.md](RISKS.md)。

## 源码运行与测试

导入项目方法沿用 [源码与构建](../../godot/README.md#源码与构建)。开发环境需可用的 Godot 版本及导入后的资源；构建工具还需 Python。未安装或未执行的工具不得记为已验证。

既有命令集中于根 [README：开发与验证](../../README.md#开发与验证)，按变更选用，不默认全部运行：

|影响范围|对应检查|
|---|---|
|规则、卡牌、AI|`godot/tests/test_engine.gd`|
|协议、认证、隐藏信息、重连|`godot/tests/test_network.gd`|
|场景与输入交互|`godot/tests/test_scene_ui.gd`；需要真实窗口时使用既有 UI 探针|
|联机界面|`godot/tests/network_ui_probe.gd`|
|公开事件音画|场景与联机UI探针须开启动画/音效验证去重、死亡及双端播放；再用真实Windows窗口检查画面与试听。仅调用播放器或headless计数不证明音质|
|取消、编号与异常动作等特定回归|先定位 `godot/tests/review_client_probe.gd` 或 `review_engine_probe.gd` 的相关检查，再按当前问题执行|
|导出行为|根 README 的 EXE `--ui-probe` 命令；需要实际图形窗口，headless 结果不能替代|

2026-10-10 的既有历史结果见 [最终测试](../../godot/docs/代码审查与测试.md#最终测试)。本页列出操作入口，不代表已执行全部命令；最近实际执行范围与结果见 [NOW：本轮核验](NOW.md#本轮核验)。执行须记录命令、对象、退出结果和证据，不能借用旧报告作为新通过结果。

## Windows 构建与整理包

命令及模板获取方式沿用 [Godot 源码与构建](../../godot/README.md#源码与构建) 与根 [开发与验证](../../README.md#开发与验证)。

- `--build-only` 导出 EXE；先确认 Godot 可执行文件和 Windows 模板，模板下载需网络，已有有效模板可复用。
- `--package-only` 整理既有 EXE，不重新导出；前置条件是对该 EXE 已有适用的验证证据。脚本参数存在或文件大小检查通过不等于游戏通过测试。
- 包名读取`project.godot`的主/次版本，2.1生成独立`v2.1`ZIP，保留旧2.0包；升级前核对项目、导出资源版本与网络协议一致。双方必须换用同一份新版包。
- 源码变更后需要重新构建并验证相应产物，不能仅更新文档后声称包已同步。实际构建、验证与打包结果由 [NOW](NOW.md#本轮核验) 定位。
- 本地生成文件、用户验收与对外发布是不同状态；发布需对应用户授权，现状见 [NOW.md](NOW.md)。
